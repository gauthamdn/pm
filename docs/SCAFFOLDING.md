# Local Docker setup

## Run

Start Docker with Linux containers and Docker Compose v2 or newer, then run from the repository root:

```sh
./scripts/start.sh
./scripts/stop.sh
```

On Windows, use `./scripts/start.ps1` and `./scripts/stop.ps1` in PowerShell. Scripts also work from another directory when invoked using their full path.

Start builds and waits for a healthy container. Open http://localhost:8000 to use the Kanban demo. `GET /api/health` still returns the health response. Part 3 replaced the original Part 2 smoke page with the exported frontend.

Useful commands:

```sh
docker compose ps
docker compose logs app
```

## Structure and storage

`Dockerfile` builds the frontend using Node 26 and `npm ci`, then copies the static export into a Python 3.14 image using uv 0.13.7 and locked production dependencies. FastAPI serves the API before mounting `/app/static` at `/`. Node is not included in the runtime image. The container runs as a non-root user; the published port binds only to the local machine. The setup follows the [uv Docker guide](https://docs.astral.sh/uv/guides/integration/docker/) and [FastAPI container guide](https://fastapi.tiangolo.com/deployment/docker/).

Compose mounts the named volume `kanban-studio_kanban-data` at `/app/data`. `DATABASE_PATH=/app/data/kanban.sqlite3` reserves the application database location for later stages. Normal stop scripts remove the container and network while retaining the volume. The image excludes environment files, and Part 2 needs no API key.

The app does not yet initialize the application database or define a schema. Schema approval and database creation remain in Parts 5 and 6. Board state currently resets on reload.

## Development checks

With uv and Python 3.14 installed, run from `backend/`:

```sh
uv sync --locked
uv run ruff check .
uv run ruff format --check .
uv run pytest -W error
```

The lockfile is generated by uv; update it with `uv lock` when changing dependencies. TestClient uses httpx2, as recommended by the [Starlette TestClient documentation](https://www.starlette.io/testclient/).

## Part 2 verification (historical)

- Built and started the app with `scripts/start.sh` on macOS using Docker Desktop Linux containers; the Compose healthcheck passed.
- Backend lint and formatting passed; all five API/static tests passed with warnings treated as errors in a Python 3.14 container.
- Headless Chromium loaded the real Docker-served page at 1280 x 800 and 390 x 844. Rendered HTML contained the API response, and screenshots were visually inspected.
- Wrote a separate SQLite probe into the mounted volume as the application user, stopped the app with `scripts/stop.sh`, restarted with `scripts/start.sh`, and confirmed the saved value. Removed the probe afterward; no application schema was created.
- POSIX shell syntax checks passed. Windows PowerShell and native Linux execution were not available for runtime verification.
- Browser verification used an already-installed Chromium binary. A temporary npm installation attempt was rejected for an unapproved telemetry endpoint; the scripts-disabled official-registry alternative failed certificate validation. Neither was required for the successful browser check.
